# 코딩 hard-negative 전문가 규칙

## 목표

chosen의 API·언어·전체 접근법과 정상 입력 동작을 보존하면서 **현실적인 결함 하나**를 만든다. 코드는 실행 가능하고 리뷰 전에는 쉽게 지나칠 만해야 한다.

## 권장 오류 설계

- 빈 입력, 경계값, 나머지, 중복값, 유니코드 등 엣지 케이스 하나만 놓친다.
- 동시성·자원 정리·오프바이원 중 한 문제만 국소적으로 만든다.
- 설명형 답변은 시간 또는 공간 복잡도 한 항목만 잘못 설명한다.
- 후속 요구에서 바뀐 인자·출력 형식·제약 하나만 이전 상태로 남긴다.

## 금지

- 문법 오류, 존재하지 않는 API, 타입 오류, 논리 오류를 동시에 만들지 않는다.
- 주석이나 설명에서 버그·경합·누락이 발생한다고 스스로 밝히지 않는다.
- 코드 펜스 언어명처럼 실제 동작과 무관한 표면 차이를 오류로 주장하지 않는다.

## 출력 전 내부 점검

일반적인 입력에서는 그럴듯하게 동작하고 특정 조건 하나에서만 chosen보다 나빠지는지 확인한다. 오류를 직접 폭로하는 주석이 없는지도 확인한다. 점검 과정은 출력하지 않는다.
